case study

Ellentia

A local-first, human-governed AI orchestration and knowledge system.

Python 3.12OllamaQdrantSQLitePytestJSON schemas

Models reason. The application orchestrates. The human retains authority.

The problem

Many AI apps let the model decide what to do and then do it. That blurs the line between a suggestion and a permission, makes tool execution risky, and leaves answers without traceable sources. Ellentia puts the Python application in charge of routing, validation, permissions, execution, and logging.

Architecture

  • Orchestration lifecycle: intent classification, context construction, model selection metadata, state management, and full request logging. Unsupported actions fail closed.
  • Structured response contract (ellentia.response.v1): every action request is validated against schemas, registered tools, argument rules, and permission policy before anything runs.
  • Central tool and model registries with read-only vs. approval-gated permissions and least-privilege defaults.
  • Governed memory: permanent memory requires explicit approval.
  • Retrieval-augmented generation with approved-source ingestion, Qdrant vector search, SQLite metadata, and source provenance on every chunk.

Retrieval-backed journal briefing

The /journal-brief workflow retrieves only relevant approved sources and returns a summary with citations, keeping evidence, inference, and suggestions separate. When nothing clears the 0.55 similarity threshold, it returns an explicit insufficient-evidence result instead of guessing.

A decision I'm proud of

I designed Ellentia for a council of specialist models. Two candidates, Granite 4.1 3B and Gemma 4 E4B, failed their routing evaluations. Instead of lowering the bar to ship the feature, I paused multi-model routing and kept the stable single-model architecture and its rollback baseline.

Security hardening

I audited my own system and found two gaps. The shell "read-only" allowlist checked only a command's first word, so flags like find -delete or sed -i could slip past validation. And the web app's chat route accepted writes from any website. I fixed both: every argument is now validated before the approval card appears and again right before execution, paths must stay inside the project, dangerous flags are refused, and commands time out after 30 seconds. The web app now rejects cross-site and non-local requests, which also closes a DNS-rebinding path.

A pre-push guard keeps private history from ever reaching GitHub, and personal data lives in a separate private vault, migrated with hash verification and a rollback plan.

Current status

Active development. Verified: orchestration, validation, permissions, logging, and live Qdrant retrieval against both a bounded corpus and the full journal, with 100% citation fidelity and chunk-for-chunk parity with the local fallback. When Qdrant is stopped, the system falls back cleanly to the same answers. Multi-model routing and autonomous writes stay off until they pass evaluation.

Ellentia is my private assistant, so its source code isn't public. I'm glad to walk through its architecture, evaluation suites, and tradeoffs in an interview.
